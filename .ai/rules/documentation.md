# Documentation Rules & Standards

---

## 1. Inline Code Documentation
* All PHP classes, Service methods, and Action handlers must include descriptive PHPDoc blocks specifying `@param` and `@return` types.
* Complex domain algorithms (such as priority wait time logic or pessimistic locking steps) must include inline comments explaining *why* the approach was chosen.

## 2. Examination Documentation Deliverables
Maintain up-to-date markdown documentation for the examination evaluation:
- **Software Requirements Specification (SRS)**: Problem statement, personas, MoSCoW requirements, traceability matrix.
- **Software Effort Estimation**: UCP/FPA calculations, complexity analysis, 48-hour scope breakdown.
- **System Architecture & Design**: Diagram descriptions, schema maps, API contracts.
- **User Manual**: Illustrated walkthrough for Patients (Kiosk/Display), Staff, and Administrators.
- **Maintenance & Future Evolution Plan**: Post-exam expansion roadmap.
