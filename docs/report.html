1. Executive Summary & Project Objectives

MediQueue is a modern, accessible, enterprise-grade clinic queue management web application engineered to solve the persistent operational bottleneck of physical waiting lines in outpatient healthcare facilities. In traditional clinical environments, patients endure unpredictable physical queue times, overcrowded reception lounges, and stressful verbal callouts. MediQueue replaces physical lines with a resilient, transactional digital queue engine.

1.1 Project Objectives

  • Patient Empowerment: Enable patients to join clinic department queues digitally from any mobile device, receive sequential atomic ticket numbers (e.g. GC-001), and monitor their real-time line position and estimated wait duration with asynchronous 4-second polling.
  • Clinical Operations Console: Provide doctors and nursing staff with a focused console to call the next patient, manage consultation lifecycles, handle no-shows (skip/recall), and review live department analytics.
  • Hospital Departure TV Screen: Broadcast a public, dark-mode waiting room TV display (/display) featuring huge high-contrast "Now Calling" tickets and a department-by-department status matrix with automated 3-second live sync.
  • Administrative Governance & Security: Enforce the Principle of Least Privilege across three isolated roles (patient, staff, admin), configure clinic settings and operating hours, perform administrative password resets with automated email notices, and maintain an immutable security audit trail.

2. System Architecture & Engineering Design

MediQueue is architected as a Modular Layered Monolith using Laravel 12 on PHP 8.2 with Tailwind CSS v4 and PostgreSQL. A layered monolithic architecture was selected (ADR-002) to guarantee sub-millisecond local transactional consistency without the operational latency and distributed transaction hazards of microservices.

2.1 Concurrency Safety & Pessimistic Locking

To prevent race conditions, duplicate ticket allocations, or simultaneous staff callouts during concurrent patient spikes, all queue state transitions in App\Services\QueueService execute inside atomic database transactions with pessimistic row locking: 

// App\Services\QueueService.php: Atomic Ticket Generation
DB::transaction(function () use ($patient, $service, $priority) {
    // 1. Check for existing active ticket for this patient (Pessimistic Read)
    $existing = QueueEntry::where('patient_id', $patient->id)
        ->whereIn('status', [QueueEntry::STATUS_WAITING, QueueEntry::STATUS_CALLED, QueueEntry::STATUS_IN_SERVICE])
        ->lockForUpdate()
        ->first();

    if ($existing) {
        throw new \DomainException('You already have an active ticket in the queue.');
    }

    // 2. Lock and calculate sequential sequence number for today
    $maxSeq = QueueEntry::where('service_id', $service->id)
        ->whereDate('joined_at', today())
        ->lockForUpdate()
        ->max('sequence_number') ?? 0;

    $nextSeq = $maxSeq + 1;
    $queueNumber = sprintf('%s-%03d', $service->prefix, $nextSeq);

    // 3. Persist new queue entry atomically
    return QueueEntry::create([
        'patient_id'      => $patient->id,
        'service_id'      => $service->id,
        'queue_number'    => $queueNumber,
        'sequence_number' => $nextSeq,
        'status'          => QueueEntry::STATUS_WAITING,
        'priority'        => $priority,
        'joined_at'       => now(),
    ]);
});

3. Queue Finite State Machine

Every queue ticket strictly adheres to a deterministic finite state machine. Invalid state mutations (e.g. attempting to complete an uncalled ticket) throw validation domain exceptions.

Current State Target State Triggering Actor Operational Meaning
WAITING CALLED Clinical Staff Staff triggers "Call Next"; assigns patient to doctor's desk.
WAITING CANCELLED Patient / Admin Patient withdraws ticket before consultation starts.
CALLED IN_SERVICE Clinical Staff Patient reports to room; medical consultation commences.
CALLED SKIPPED Clinical Staff Patient fails to respond to callouts; moves to skipped pool.
SKIPPED CALLED Clinical Staff Skipped patient arrives at reception; recalled to active call.
IN_SERVICE COMPLETED Clinical Staff Consultation concluded (Terminal state; computes wait duration).
